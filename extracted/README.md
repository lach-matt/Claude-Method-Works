# `extracted/` — the artefacts that were sealed inside the mirror

`drive/` mirrors Google Drive byte-exactly, and 31 of the files it holds are **archives**
(`.zip`, `.tar.gz`) with a further 9 that are **Claude project exports** (`.json` with a `docs`
array). Their contents were in the repo only in the sense that a locked box is in a room: present,
inventoried, unreadable without unpacking. This tree unpacks them, once, into one place.

Generated by [`../tools/consolidate.py`](../tools/consolidate.py) — **never hand-edit it**, and
never hand-edit `LEDGER.tsv`. Regenerate with `python3 tools/consolidate.py`; check it with
`python3 tools/consolidate.py --verify`.

## What is here

| | Files | Bytes |
| --- | ---: | ---: |
| `archives/` — unpacked from the 31 archives | 746 | 51,167,078 |
| `projects/` — docs from the 5 projects that have any | 33 | 6,233,414 |
| **Total distinct bodies** | **779** | **57,400,492** |

Among them: **384 `.py` instruments**, 4 session **transcripts** (1.9 MB), 80 figure `.png`s,
189 `.tsv` data tables, and the `COORDINATES.tsv` / `channels_map.json` / `index_final.json` /
`survey.json` data set from the 2_13 restore point.

`PROJECT-INDEX.tsv` lists all **9** projects — uuid, name, timestamps, doc count, extract dir.
Four are empty in the export (`The Method` is not: 33 docs) and get no directory.

## Nothing here is a second copy

`LEDGER.tsv` has **one row per source occurrence — 2,504 of them** — and every row says where that
occurrence ended up. Only 779 became files:

| Disposition | Rows | Meaning |
| --- | ---: | --- |
| `EXTRACTED` | 779 | written to `target_path` |
| `DUP-OF-EXTRACTED` | 1,198 | identical md5 already written from an earlier source; `target_path` names the one copy |
| `PRESENT-IN-REPO` | 523 | already tracked under `drive/`, `method/`, `tools/` or `docs/`; `target_path` names it |
| `SKIPPED-DERIVED` | 4 | `.pyc` bytecode, which `.gitignore` excludes |

Deduplication is by md5 over the file body, so **188,280,626 bytes of duplicate content were
resolved to a pointer instead of written**. To find every place a body came from, grep its md5 in
`LEDGER.tsv`: `COORDINATES-2_13.csv` alone appears in three projects and is stored none of those
times, because `drive/` already had it.

Archives are visited canonical-copy-first, so a body lands under the plain archive name rather than
a `__<driveFileId>` or `-1` variant. That is why `method16_rp_A_instruments.tar.gz`,
`method16_rp_C_figures.tar.gz` and `The_Method_1_6_figures_complete.zip` have no directory of their
own — every one of their members was already written from `restore-point-2_13.tar.gz`, which sorts
first. The transcripts from `rp_C` are at `archives/restore-point-2-13/transcripts/`. The ledger
resolves each of those members to its target.

## Two things the ledger records that are easy to get wrong

**A project doc named `.pdf` or `.docx` does not hold a PDF or a Word file.** The export stores
`content` as *text*; the binary is not in it. Those four docs are written with `.txt` appended —
`The Method 1.6-10.pdf.txt` — and the `note` column says so. Do not treat them as the originals;
the real PDFs are in `drive/`.

**Two project docs differ from their `CORPUS` twins by exactly one trailing newline**
(`INTEGRATION-transitions.md`, `RESPONSE-TO-METHOD-1_6.md`). They are not byte-identical, so they
are kept rather than silently collapsed, and the difference is a finding, not a defect to repair.

## What is still not here

Unchanged by this pass, and still listed in [`../drive/PENDING.tsv`](../drive/PENDING.tsv):

* **The two 388 MB `conversations.json` chat exports** — the full transcript store. Above GitHub's
  100 MB per-file hard block, and far above the ~6 MiB payload ceiling of the Drive connector, so
  no transfer method available here can bring them in. Shard them with
  [`../tools/shard_conversations.py`](../tools/shard_conversations.py). The 4 transcripts in this
  tree come from a restore point and are not a substitute for that store.
* **`BUILD174` third copy and `BUILD178` second copy** — same-folder Drive duplicates, reachable
  only by Drive id via `tools/drive_sync.py --only`.

## `drive/` is untouched

This pass reads `drive/` and writes nothing to it. Its 819-row `MANIFEST.tsv` ↔ 819-file bijection
holds exactly as before, and `tools/drive_sync.py` would report no local extras. Provenance runs
one way: `drive/` is the mirror of record, `extracted/` is derived from it and reproducible.
