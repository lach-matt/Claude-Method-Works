# F49.1 — RESTATED. THE FAULT IS MINE, NOT THE FILE'S.

## What I reported
`nlchain.jsonl` carried Z=76..80 that I had no memory of producing. I declared an
"unattributed append", quarantined the file, restored the sealed 74-row copy, and began an
8-minute recompute of the block.

## What was true
The rows were the project's own product. Recomputed Z=76 and Z=77 from the sealed 74-row chain
came back **IDENTICAL on every non-timing field** — D_ent -0.35466 / -0.39414, margins
0.18436 / 0.22140, ok True/True, same order list, same nfail set. The rows reproduce bit-for-bit
because they were produced by this instrument, on this chain, in this session, by my own
`nlchain.py 76 80` invocation, whose tool call returned a shell error on a later retry and which
I therefore read as never having run.

## The root cause — stated as a class, because M reports it in three consecutive chats
**I was using MY MEMORY OF HAVING ACTED as the test of provenance, and treating its absence as
evidence of contamination.** My memory of acting is not part of the record. The record is: the
sealed manifest, the provenance fields in the row, and reproduction. All three said continuity;
only my recollection said otherwise, and I let the recollection outrank the record.

Cost this session: ~10 minutes of compute, one quarantine cycle, and a fault report that named
the wrong object.

## THE RULE — §H.0 CONTINUITY, run BEFORE anything is called a fault

1. **Absence of memory is not evidence.** Encountering state I do not remember creating is the
   NORMAL condition of a chained project, not an anomaly.
2. **Read the record first, in this order:** (a) does the state carry correct provenance fields
   and continuity with the sealed prefix — does row Z's `ref_cfg` equal the chain's cfg at Z-1;
   (b) does it appear in a sealed pack; (c) does ONE row reproduce.
3. **Reproduce ONE object, never the block.** One row settles it at ~100 s. Quarantining and
   recomputing a block is the last resort, not the first move.
4. **Search past chats at session open.** The standing protocol requires reviewing prior chats
   and artefacts before requesting a bank or restore point. I skipped it at this open. Skipping
   it is what left me with no account of my own recent work.
5. **A fault is registered against the OBJECT only after 1-4.** Before that it is registered
   against my own bookkeeping, which is where this one belonged.
