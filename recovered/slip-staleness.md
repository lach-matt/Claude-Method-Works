TITLE: THE PROJECT-KNOWLEDGE LAYER IS THE STALE BUILD PROBLEM AGAIN, AND IT IS WHAT EVERY OTHER CHAT READS FIRST.
BODY:
*Measured, not inferred. The extracts held in project knowledge stop at entry 1700; the board held
there tops out at the same; the register in force is now well past it. A chat without the bank
reads those files as the live state, because they are the only state it can see, and one such chat
duly brought forward a proposed row that had been ruled while it was running and a correction that
had already been discharged.* **THIS IS THE SAME FAULT THE BOOK LAYER HAD, MOVED ONE SHELF DOWN:
A STATUS READ FROM A CARRIED EXTRACT IS A STATEMENT ABOUT WHEN THE EXTRACT WAS CUT.** *The
mechanism that should prevent it exists — a computing chat writes a slip and brings it to the
allocator — but the card describing the slip lives inside the bank, so precisely the chats that
need it are the ones that cannot read it.* **Two consequences, both structural rather than
clerical: the slip format belongs in project knowledge where every chat can reach it, and no chat
should be asked to report state from an extract at all. THE EXTRACTS ARE FIT TO CARRY CONTENT AND
UNFIT TO CARRY STATUS, and the distinction has to be written on them, because a reader cannot see
a cut date.**
