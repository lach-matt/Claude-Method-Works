## Discrepancy A — the Index of Indices tower table

The Index of Indices prints the tower's cell counts at Λ₁₂ and Λ₁₃ as **22,275 and 64,290**. The Request-3 rebuild reproduced the §12.11.0.10 figures as **70,905 and 199,130** (the f_max build), and a cell's-f law variant gives **55,755**. So the printed 22,275 / 64,290 matches **neither** build tested.

**Questions:**
- A1. What build/capping produces 22,275 and 64,290? Is it a stale table from a superseded cap, a different f-convention, or an error?
- A2. Which figures are canonical for the tower — 70,905 / 199,130 (f_max, matching §12.11.0.10 and the time chapter's "Every Λ in one table"), or something else? We need the one set that every volume must agree on.
- A3. The exact one-line correction for the Index of Indices entry, once A2 is fixed.

**Why it matters for repair:** the time chapter's tower table and MC-55's rebuild both use 70,905 / 199,130. If those are canonical, the Index of Indices is stale and gets corrected to match. If 22,275 / 64,290 are correct under some capping the rest of the book also uses, then the time chapter and §12.11.0.10 are the ones in error — a much larger repair. We need to know which before touching anything.

## Discrepancy B — the axis-10 "parity" annotation at §12.11.3.1

§12.11.3.1 annotates axis 10 (the v / seniority axis) as **"parity."** The Request-3 return found this annotation belongs to the **exact physical set, not the admissible bound**: parity builds give **1,841** cells against the printed **2,535**, while the bare interval bound gives **2,535 exactly**. So the printed count (2,535, which the whole tower uses) is the bare-interval bound, and the "parity" label misdescribes it.

**Questions:**
- B1. Confirm: is the axis-10 count canonically 2,535 (bare interval 2S′ ≤ v ≤ g), with "parity" an incorrect annotation to be struck or corrected?
- B2. If parity is a real physical property of axis 10 that belongs somewhere, where does it belong — the exact-set discussion, a compendium note — rather than on the admissible bound?
- B3. The exact one-line correction for §12.11.3.1's annotation.

**Why it matters for repair:** 2,535 is load-bearing — it is in the time chapter's tower table and in MC-22/MC-23's axis table. If 2,535 is right and only the label is wrong, the repair is a one-word annotation fix. If the parity build (1,841) is the intended count, that changes the tower's cell counts, which would cascade. We need B1 settled first.
