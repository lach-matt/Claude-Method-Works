# `lowdin/` — the Löwdin project's own walk instrument, recovered from the chat export

The Löwdin project (100 conversations in `drive/chats/`, `LCP2` to `LCP101`, sessions 4 to 104)
built the scalar-relativistic self-consistent-field chain that `THE-LOWDIN-SOLUTION-2.md` §II.2
states and register 1701 witnesses, sealed it in `LOWDIN-HANDOFF-103.tgz` (1,870 files), and never
banked the archive: `LW1-README.md` records objects 1, 2, 4–8 and 10 as PENDING BANK, and the site
carried a reconstruction (`tools/lowdin_walk.py`) in its place. This tree is the instrument itself,
read out of the export.

Generated by [`../tools/lowdin_recover.py`](../tools/lowdin_recover.py) — **never hand-edit it**,
and never hand-edit `LEDGER.tsv` or `WITNESS.tsv`. Regenerate with `python3 tools/lowdin_recover.py`;
check it with `--verify`; its fixtures are `--selftest`. See `docs/LOWDIN-RECOVERED.md`.

## What is here

| | |

| `LEDGER.tsv` | one row per file: bytes, sha256, how it was rebuilt, the tool call that created it and the last that changed it, how many printed windows it reproduces, the sessions that printed it whole, the sealed sha256 where the sessions printed one, and its status |

| `chain/` | what the recovered instrument returns when run here: Λ_chain to Z = 120, the c → ∞ tables, and `RUNS.tsv` naming the command, the environment and the status of each |

## How a file was recovered

A file uploaded to a chat has no content in the export, so the archive's bytes are not here. But
every runtime file was **written** in a chat by a tool call, **edited** by tool calls, and
**printed back** by `cat` and `sed -n` into tool results the export carries verbatim. Each file is
rebuilt two ways and the two are held against each other: the whole edit history replayed in order
(`create_file` bodies, `str_replace` edits, heredocs, the sessions' own in-place patch scripts and
`sed -i` commands re-executed in a sandbox), and every window the sessions printed, which the
rebuilt text must reproduce. Where the sessions printed a sealed sha256 manifest line the digest is
checked: `cinf.py` and `rt/t7b_hf.py` match theirs, and `nlchain.py` replayed to the point before
its session-47 edits hashes to the sealed `pack40/nlchain.py` line — the replay reproduces sealed
bytes.

Statuses, never flattened: **RECOVERED** (a verbatim print, or every window after the last edit
reproduced), **RECOVERED-REPLAYED** (the replay carries the file past its last print),
**RECOVERED-PARTIAL** (`t7c_cuaudit.py` alone: a composite of two prints with the session-28 patch
replayed, its later edits unrecorded; it serves the field's correlation potential, which the chain
never calls), **STORE** (`ground.py` is the store's own `LW1-ground.py`). `eps0a_table.json` is not
a file of this tree: the runtime generates it with the record's own generator over its ring
integral, and the six rows the session printed are the check.

## What it is not

Not the sealed archive, whose 1,870 files include run receipts, caches and the session documents
(the session documents are in `recovered/`). Not a reconstruction: nothing here is rebuilt from a
statement of behaviour. Not a repair: where the record's own instrument disagrees with the record's
sealed rows, the disagreement is reported with the record's own fault beside it.
